1.1 — Finite Difference Operator

Implementation — 4-loop Convolution

def convolution_4loops(
    img: np.ndarray,
    K: np.ndarray, #kernel
    use_padding: bool = True,
    flip: bool = True, #flip kernel for conv
) -> np.ndarray:
    """
    2D conv using 4 loops:
    - If `use_padding`: zero-pad by (kH//2, kW//2) to return same-size output.
    - If `flip`: flip kernel for convolution; otherwise computes correlation.
    - Returns array with shape (H, W).
    """
    H, W = img.shape
    kH, kW = K.shape
    if use_padding:
        pad_h, pad_w = kH // 2, kW // 2
        img = pad_zero(img, pad_h, pad_w)
    out = np.zeros((H, W), dtype=img.dtype)
    if flip:
        K = np.flip(K, axis=(0, 1))
    for out_row in range(H):
        for out_col in range(W):
            for kernel_row in range(kH):
                for kernel_col in range(kW):
                    out[out_row, out_col] += img[out_row + kernel_row, out_col + kernel_col] * K[kernel_row, kernel_col]
    return out

Implementation — 2-loop Convolution

def convolution_2loops(
    img: np.ndarray,
    K: np.ndarray, #kernel
    use_padding: bool = True,
    flip: bool = True, #flip kernel for conv
) -> np.ndarray:
    """
    2D conv using 2 loops:
    - If `use_padding`: zero-pad by (kH//2, kW//2) to return same-size output.
    - If `flip`: flip kernel for convolution; otherwise computes correlation.
    - Returns array with shape (H, W).
    """
    H, W = img.shape
    kH, kW = K.shape
    if use_padding:
        pad_h, pad_w = kH // 2, kW // 2
        img = pad_zero(img, pad_h, pad_w)
    out = np.zeros((H, W), dtype=img.dtype)
    if flip:
        K = np.flip(K, axis=(0, 1))
    for out_row in range(H):
        for out_col in range(W):
            out[out_row, out_col] = np.sum(img[out_row:out_row + kH, out_col:out_col + kW] * K)
    return out
Timing summary.
My 4-loop convolution takes about 50 seconds, with my 2-loop convolution taking 4 seconds and the scipy convolve2d taking .231 seconds. Here it is clear that each of these versions is an order of magnitude faster than the last. I found it interesting how much faster scipy's convolve is, likely due to being heavily optimized code.

Both my implementations and scipy convolve2d have Box blur near borders getting darker (averaging in zeros with the padding). Overall these techniques all produce the same effect. Scipy's convolve2d has different options for padding, such as 'fill' (default): Similar to zero-padding, 'wrap': opposite edges connect, 'symm': Reflects pixels across boundaries, and 'constant': Uses a set constant value. I used 'fill' for this project to mimic zero-padding.
Here we see the finite difference operators (Dy/Dx) successfully highlight horizontal/vertical edges, respectively. We can also see that derivatives (Dx/Dy) at the very edge tend to show large responses because the outside is 0. This is expected for zero-padding, but in practice we might want to use a different padding strategy (e.g., reflect) to avoid this artifact.

2.1 — Image Sharpening

In this exercise, I explored how to sharpen images using frequency-based filtering. The idea is to separate an image into its low-frequency (slowly varying content) and high-frequency (edges and fine details) parts.

The Gaussian filter acts as a low-pass: it suppresses high-frequency details. Subtracting this blurred version from the original isolates the high-frequency component. Adding some scaled amount of that component back to the original enhances edges and makes the image appear “sharper.”

Sharpening

The sharpening process can be described in two steps:

  1. Blur the image with a Gaussian filter G.
  2. Subtract the blur from the original to extract high frequencies, then add them back with scale alpha.

Formally:

Isharp = I + α · ( I − ( I * Gσ ) )
The first thing I thought to do was to pick a sigma (standard deviation of the gaussian) that would be appropriate for the 300 x 300 pixel image. I saw that many of the details I wanted to extract were quite fine, maybe 2–5 pixels. I ultimately decided on a sigma of 1.5 which gives a kernel size of about 11 x 11 (similar to what I used earlier) which seemed to blur effectively enough so that the difference between the original image and the blurred image captured the highest frequencies (i.e. the taj majal’s structure and the bushes lining the path). Next I had to choose how much of these high frequencies to add back to the image (how much sharpness to add). I tried 4 different values [0.5, 1.0, 1.5, 2.0] and liked 0.5 the most visually since it did not look overly rigid or grainy but still managed to make the key features of the image sharper and more visually appealing.

My first approach for given image I was: 
I + alpha (I - gaussian(I, sigma))
In order to make these one operation I rearranged the equation: 
I + alpha (I - gaussian(I, sigma))  = (1 + alpha) * I - alpha * (gaussian(I, sigma))
Since convolution is linear this can be one convolution with image I, if we define the convolution: 
(1 + alpha) * unit impulse kernel  - alpha * gaussian kernel
(Comments on Sharpening a Sharp Image): I picked a sharp waterfall image to try to sharpen further and it did get slightly sharper but also seemed to get somewhat more coarse. By coarse I mean that parts of the image looked a bit grainier, meaning that there are limits to how different the sharpening can make it. I picked a bigger sigma in order to blur more effectively since my image size was bigger (more pixels) to pick out the higher frequencies easier.

2.3 —Gaussian/Laplacian Stacks

Comments: I built both Gaussian and Laplacian stacks from scratch. The main idea of a stack is that unlike a pyramid, the images are not downsampled at each level — every level stays the same size as the original. To make the Gaussian stack, I repeatedly blurred the image with a Gaussian filter. This keeps the levels aligned pixel-by-pixel, just with progressively smoother detail.

The Laplacian stack is then made by subtracting each blurred level from the previous one. This captures the band-pass (edges and fine details) at different scales, while the last level is just the heavily blurred Gaussian. Adding all Laplacian levels back together reconstructs the original image (which was helpful for debugging).

For the Oraple example, the Laplacian stack shows how fine details of the apple and orange are preserved at shallow levels, while broader color/shape differences appear in deeper levels. The Gaussian mask stack controls how much of each image contributes at each frequency. When summed, the results blend smoothly.

2.4 — Creative Blends (Masks + Results)

Each row shows: Original A, Original B, Mask, Final Blend.

Comments: For the apple + orange blend (“oraple”), I used a simple vertical step mask. This made sense because both images had a clear left/right structure, and the seam could fall naturally in the middle. Using a Gaussian stack for the mask blurred the transition so that the seam wasn’t harsh, and the textures of the apple and orange flowed together. For the moon + cheese, I designed a circular, feathered mask. The idea was to mimic the round shape of the moon and then fade in the cheese texture from the center. Without feathering, the seam was obvious, but with a Gaussian-blurred radial mask the textures mixed smoothly and the “moon made of cheese” illusion worked well. For the tree + broccoli, I used a diagonal feathered mask. A straight vertical or horizontal seam looked artificial since the shapes didn’t align well. The diagonal mask let the top of the broccoli merge into the tree canopy more naturally. Feathering was especially important here, since the fine texture of the leaves would have made a hard seam very noticeable. In all cases, the Gaussian stacks of the mask were critical: they softened the boundaries and eliminated harsh lines. The blends weren’t perfect—there are still slight artifacts where textures differ strongly (like the bark vs. broccoli stem), but overall the feathered masks allowed convincing composites.
